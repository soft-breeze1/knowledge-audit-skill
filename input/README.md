# input 目录说明（自带演示数据）

本目录存放**待审查的企业知识库 Markdown 文档**（`.md` / `.markdown`），并自带一套演示数据：
内容按企业技术规格书 / 选型手册的写法组织，**机型与参数均为虚构演示数据**，并**故意保留了一处取值冲突**，
便于直接试跑并核对报告结论。

## 自带演示数据

- `example.md`：转写质量缺陷演示（OCR 标记残留 1 处、占位符文本 2 处）；另留有表格结构写法（表格列数与表头不一致、
  空单元格）、空章节、疑似截断，以及“缺失/空图片引用、标题格式异常、连续空行”等写法，用于验证这些
  **不在检查口径内**的写法不会出现在报告里。
- `products/机器ABCDEF-100_技术规格书.md`：规格书式参数表（六列并排的“项目-单位-参数”表、
  三列“项目-参数-单位”表）；型号 `机器ABCDEF-100`，其中“操作重量 12300 kg”。
- `products/机器ABCDEF-100_选型手册.md`：折页式排版表（表头含“单位mm”，同行相邻的“标签-数值”对，
  如 `A 总长` 与 `8800`、`操作重量/kg` 与 `12400`、`回转速度/r/min` 与 `12.5`）。

## 检查口径（固定 6 项检查，分类即检查项）

| 检查项 | 说明 |
| --- | --- |
| 编码可解码性（UTF-8） | 文件能否按 UTF-8 解码；解码失败的字节就是损坏处 |
| 替换字符 U+FFFD | 解码失败留下的占位字符，原内容已丢失 |
| 编码乱码特征 | 编码转换后出现的典型乱码字样（规则见 `rules/ocr_patterns.json`） |
| OCR 标记残留 | 方括号 OCR / 图片 / 表格 一类残留标记（规则见 `rules/ocr_patterns.json`） |
| 占位符文本 | 未补全的待办类英文标记与中文“待补写”一类表述（规则见 `rules/ocr_patterns.json`） |
| 空文件检测 | 0 字节文件，可能是转写失败或占位文件 |

- 报告与清单表格的「问题类型」就是上面的检查项名称（分类即检查项，不再有「门类 · 检查项」两级写法）；
- **统计口径单层**：这 6 项的问题**全部**计入审查概况的「存在问题文件数 / 问题总数」，并逐行写入清单表格
  ——不再有「注意项」，也不存在“口径外的行”；
- 表格列数与表头不一致、表格空单元格、空章节、代码块未闭合、疑似文本截断等结构类写法**不在检查口径内**、
  **不产生任何问题**；代码块内部只检查替换字符与编码乱码特征（避免把示例代码误报为占位符 / OCR 标记）；
- 读取失败 / 超过单文件大小上限的文件属于“漏审风险”，不计入「存在问题文件数 / 问题总数」；数量与文件名会在控制台提示，并写入 HTML 报告「附：本次运行信息」。

## 预期结果（试跑后可对照）

- **质量审查**：扫描 4 个文件，**存在问题文件数 1、问题总数 3 处**，全部在 `example.md`
  （OCR 标记残留 1——行 10；占位符文本 2——行 35、44）；`products/机器ABCDEF-100_技术规格书.md`、
  `products/机器ABCDEF-100_选型手册.md` 与本文件（`input/README.md`）自身 0 处。
- **不在检查口径内的写法（不产生问题、不出现在报告里）**：`example.md` 的表格结构（表格列数与表头不一致 1、
  表格空单元格 2，行 20-21）、空章节（行 50）、疑似截断（行 54），以及 `products/机器ABCDEF-100_选型手册.md`
  排版表中的留白单元格（行 9-14）——按现口径**全部不上报**，报告与清单表格里都不会出现。
- **属性冲突比对**：抽取 42 条“属性=数值+单位”记录，形成 17 组可比对的同型号同属性记录（即报告概况的
  「含相同属性数量」），其中 **1 组「相同属性但描述不一致」**——型号 `ABCDEF-100` 的“重量”
  （技术规格书写“操作重量 12300 kg”，选型手册写“操作重量/kg 12400”）；其余 16 组
  （总长/总宽/总高、回转速度、功率、斗容、最小离地间隙等）描述一致，只计入比对概况的数量而**不列出**。

## 使用方法

```bash
python scripts/run_all.py input/            # 一条命令：质量审查 + 属性冲突比对
```

也可以不给本地目录，直接给**在线知识库地址**（先自动抓取库里已转写好的 Markdown 再审查）：

```bash
python scripts/run_all.py --url "https://kb.example.com/knowledge/asset" --token "<x-access-token>"
python scripts/fetch_knowledge.py "<知识库列表页地址>" --token "<x-access-token>" --output input/kb   # 只抓取，便于先看抓到哪些文档
python scripts/fetch_knowledge.py "<知识库列表页地址>" --token "<x-access-token>" --limit 0 --all-assets   # 全量抓取列表内全部资产
```

- 默认只抓**有效文档**（文档类型 / 有效状态 / 质量通过），且**同一文档只抓第一份**：同一路径只保留第一份，每份只取第一个版本，重复项与历史版本跳过；`--any-quality` 放宽质量状态，`--all-assets` 抓取列表内**全部资产**（不做任何过滤，配合 `--limit 0` 即全量抓取）；
- 抓取结果按知识库的目录结构写成 `.md`（文件名追加 `.md`、保留原始扩展名以便追溯来源），默认最多 200 篇（`--limit` 可调，`0` 为不限制）；
- 用 `run_all.py --url` 时，抓下来的 Markdown 属**输入缓存**，写入 `output/_kb_source/<时间戳>/`，交付文件仍只有 4 个（2 HTML + 2 XLSX）。

或分步执行（每次运行产出 **HTML 报告 + XLSX 清单表格** 两份交付文件）：

```bash
python scripts/audit_markdown.py input/     # ① 转写质量审查
python scripts/detect_conflicts.py input/   # ② 同一型号属性冲突比对
```

每次运行都会在 `output/` 下新建一个**带完整时间戳的子目录**（如 `output/20261023-160033/`），
共 4 个交付文件——`知识库文档解析与转写质量问题报告.html/.xlsx` 与
`知识库同类属性冲突审查报告.html/.xlsx`——全部放在该目录内，一次任务一个目录、不会互相覆盖；
只输出 HTML 与 XLSX，**不产生任何 Markdown / JSON 文件**。

- `.html` 便于阅读：质量报告按文件分组、逐条给出行号与证据原文；冲突报告按「型号 + 属性 + 工况」列出各来源文档与取值；
- `.xlsx` 便于筛选：质量清单表格一行一处问题（文件、行号、问题类型、问题说明、证据原文，
  「问题类型」就是 6 项检查的检查项名称，6 项**全部写入**、不存在口径外的行），冲突清单表格一行一处来源取值
  （冲突编号、型号、属性、描述、来源文档、行号、证据原文）。表格由标准库生成、无需第三方库：
  表头深蓝底白字、列宽已加宽、单元格带边框、隔行浅蓝斑马纹、首行冻结并开启自动筛选，Excel / WPS 双击即可打开。

## 注意事项

1. 正式使用时，请清空本目录的演示数据，改放入自己的知识库 Markdown（支持子目录递归扫描、中文文件名）。
2. 不要把手写笔记或生成的报告复制回本目录：报告应保存在 `output/`（每次运行的时间戳子目录），扫描时会自动排除输出目录与报告文件本身。
3. 本技能只审查 Markdown 纯文本：输入可以为 `.md` 文件夹、单个 `.md` 文档，或一个在线知识库文档列表页地址
   （`--url` + `--token`，此时工具只抓知识库里**已经转写好的 Markdown**）；三种输入都**不需要原始 DOCX/PDF/图片**，
   工具也不会去读取或对照原始文件。
